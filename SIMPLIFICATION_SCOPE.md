# Simplification Scope — Publish hostdb to npm

Revised 2026-05-15. Replaces the prior draft.

Single change in scope: **publish the existing hostdb npm package and have spindb import version data from it.** Items #2–#5 from `SIMPLIFICATION_IDEAS.md` are deferred to separate decisions.

---

## What we're doing

hostdb's `package.json` is already configured to publish (`private: false`, `publishConfig: {access: "public", provenance: true}`, `files: ["bin", "cli", "lib", "databases.json", "releases.json", "downloads.json"]`). It has never been published.

We:

1. Add a small resolver API to `lib/` so consumers can ask "what's the latest patch in MariaDB 11.4?" without re-implementing the logic.
2. Add a `defaults` block per engine to `databases.yml` to preserve the existing LTS-vs-latest policies (MongoDB `'8'` → 8.0 LTS, MariaDB `'11'` → 11.8 latest, etc.) that today live only as comments in spindb's hand-written MAPs.
3. Publish `hostdb@0.31.0` to npm via OIDC.
4. Replace spindb's 21 `engines/<X>/version-maps.ts` files with 5-line wrappers that import from `hostdb`. One PR per engine into spindb `dev` over ~1 week.
5. Ship `spindb@0.50.0`, bump cloud `ARG SPINDB_VERSION` via the dev → main PR flow.

**Estimated work: 2–3 days focused. Calendar: ~3 weeks** (including a 2-week soak after the May 2026 patch wave before starting, plus per-engine PR pacing).

## Critical pre-flight: defaults block

The existing MAPs encode inconsistent policies that a naive "highest version with this prefix" resolver would silently flip:

- **MariaDB** `'11'` → `11.8.6` (latest, not the 11.4 LTS)
- **MongoDB** `'8'` → `8.0.23` (8.0 LTS, not the latest 8.2.9)
- **PostgreSQL** `'17'` → `17.10.0` (only one track)

The fix is to write the rules down explicitly in `databases.yml`:

```yaml
mariadb:
  defaults:
    "10": "10.11.16"
    "11": "11.8.6"      # latest, NOT LTS — explicit
  versions:
    10.11.16: true
    11.4.10: true
    11.8.6: true
    # ...
mongodb:
  defaults:
    "7": "7.0.34"
    "8": "8.0.23"       # LTS, NOT latest 8.2.9 — explicit
  versions:
    7.0.34: true
    8.0.23: true
    8.2.9: true
```

The resolver checks `defaults` first; falls back to "highest non-deprecated version with this prefix" only when no explicit default is declared.

**Before publish:** write a test that, for every engine, calls `resolveVersion(engine, key)` for every key in spindb's current MAP and asserts the result matches the current MAP value exactly. If anything diverges, decide whether the current MAP is correct (then fix `defaults`) or wrong (then ratify the new behavior). Don't publish until the test is green.

## API surface

```ts
// hostdb's published exports

import type { Platform, DatabaseEntry, CliTools } from 'hostdb'

resolveVersion(engine: string, version: string): string | null
  // 'postgresql', '17'    → '17.10.0'
  // 'mariadb',    '11'    → '11.8.6'  (from defaults block)
  // 'mongodb',    '8'     → '8.0.23'  (from defaults block — LTS, not 8.2.9)
  // 'sqlite',     '3.53.1' → '3.53.1' (identity)
  // unknown               → null

normalizeVersion(engine: string, version: string): string
  // returns input unchanged on unknown — matches current spindb behavior

listEngines(): string[]
listVersions(engine: string, opts?: {
  format?: 'full' | 'major' | 'major-minor',
  includeDeprecated?: boolean,
}): string[]
getSupportedMajorVersions(engine: string): string[]
getMajorDefault(engine: string, major: string): string | null
getEngineDefaults(engine: string): { defaultVersion: string; latestVersion: string }

getReleaseInfo(engine: string, version: string, platform: Platform):
  { url: string; sha256?: string; sha3_256?: string; size: number } | null
getAvailablePlatforms(engine: string, version: string): Platform[]

isVersionDeprecated(engine: string, version: string): boolean
getCliTools(engine: string, version: string): CliTools
getDatabaseEntry(engine: string): DatabaseEntry | null
```

**Resolution algorithm:**

```
resolveVersion(engine, input):
  if input ∈ releases[engine].versions: return input          // identity
  if input ∈ databases[engine].defaults:                       // explicit policy
    return databases[engine].defaults[input]
  if input matches 'X.Y':
    return highest non-deprecated version starting 'X.Y.'
  if input matches 'X' (and no defaults['X']):
    return highest non-deprecated version starting 'X.'
  return null
```

## Rollback

| Failure | What to do |
|---|---|
| Bug in hostdb resolver — wrong version returned | Publish `hostdb@0.31.1` with fix. spindb auto-picks up on next install. Cloud rolls forward via SPINDB_VERSION bump. |
| Bug in one of the 21 spindb wrappers | Per-engine PR pattern means it's localized. Revert that one PR; fix; re-merge. |
| Catastrophic — npm package fundamentally broken | spindb reverts the dep bump, publishes a `0.49.x` patch. May 2026 wave proved same-day release is realistic. Cloud rolls back via SPINDB_VERSION revert. |
